# Chat — 06 · Reconciliation Compliance (how Chat implements the frozen contracts)

> See [`00-overview.md`](./00-overview.md) for framing. This doc replaces the Phase-4
> "shared-system change requests" file. The Phase-4 CHG-C1…C12 asks were **almost all confirmations of named
> seams** — and reconciliation **froze every one of them**. So this doc states, per frozen contract, **how Chat
> now IMPLEMENTS it** (no drift), and then lists the genuinely **residual** requests carried to Phase 6. The
> authority is the frozen
> [`contract-index.md`](../../../05-refined-shared-systems-architecture/contract-index.md) +
> [`00-reconciliation-decisions.md`](../../../05-refined-shared-systems-architecture/00-reconciliation-decisions.md).

## 1. How Chat implements each frozen contract it consumes

| Frozen contract (index #) | What was frozen (recon decision) | How Chat IMPLEMENTS / consumes it (no drift) |
|---|---|---|
| **`myelin-content` taxonomy** (13.1, X-2) | The canonical block set + the markdown-subset inline string + the three structured nodes; Chat consumes a **strict subset**, no collaborative-edit engine. | Chat's composer + `message` body consume exactly the frozen Chat subset (`paragraph, heading(1..3), bullet_list, ordered_list, task_list, blockquote, code_block, callout, table, divider, image` + `mention`/`artifact_ref`/`embed`); **excludes** `db_view, sync_block, toggle`; **per-message CAS on edit** (`edited_seq`), no CRDT. Reuses the WASM-compiled Rust core (one editor render path; `render(parse(md)) === md`). [01 §1.4](./01-tech-and-data-model.md). |
| **`#sub` grammar + tombstone ladder** (5.7, X-4) | One frozen `#sub` vocabulary; Refs stores full sub-URN + stripped root; one 4-step tombstone ladder; stable opaque ids minted by each owner. | Chat mints `message-<message_id>` and `thread-<thread_root_id>` (the frozen Chat kinds), stable opaque ULIDs, **immutable across edits** (the stability obligation is Chat's). Unfurl resolution degrades through the 4-step ladder; a gone/erased message → Tombstone carrying the root. [03 §2](./03-events-contracts-and-glue.md), [02 §4.2](./02-internals-and-algorithms.md). |
| **`list_objects` `SetExpr` push-down** (4.3, OQ-E) | The consumer-composable set algebra lowered to a SQL JOIN over the consumer's own id column against the per-tenant authz reverse index; no N+1, no post-filter. | The unfurl membership-class precompute lowers `SetExpr` over the candidate-id column; the Search ACL conjoin lowers it over `message.id`; read-fanout uses `list_subjects(channel, watcher)` against the same index. Zookie bounds staleness; `member_*` refreshes the class. [02 §4.3](./02-internals-and-algorithms.md), [03 §7](./03-events-contracts-and-glue.md). |
| **`check` + `CaveatContext`** (4.2, OQ-E) | Field/transition ABAC at `check`-time, off the `list_objects` hot path. | Chat's row-level visibility is the plain `channel.read`/`message.view`; **Chat does not need the field-level caveat** (that serves Issues/KN field-hiding) — it is named here for completeness, not used on the hot path. [01 §5](./01-tech-and-data-model.md). |
| **ReBAC namespace fragment** (4.9) | The Chat fragment is frozen: `channel.read = member + parent_project->read`; `watcher` relation per watchable type; performant at 50k-member density. | Chat declares the verbatim frozen fragment; membership writes project tuples via `write_tuples → zookie` (stamped on the conversation); `watcher` is the read-fanout relation. [01 §5](./01-tech-and-data-model.md), [03 §5](./03-events-contracts-and-glue.md). |
| **Firehose resume-cursor protocol** (3.5, OQ-J) | `subscribe(stream, scope, cursor?)` / `resume(stream, scope, last_seq)` / per-`(stream,scope)` `seq` / `resync_required` → `*.snapshot` / **bounded scope never `*`**. | The connection tier `subscribe`s at `scope = channel:<id>` (bounded, paginated for hot channels), `resume`s the gap `(last_seq, now]`, falls back to `*.snapshot` (= `MessageStore::resync_from`) on `resync_required`. Zero-loss-across-reconnect is the gate. [02 §1](./02-internals-and-algorithms.md). |
| **Per-effect `idem_key`** (9.1/9.4, OQ-F) | `idem_key = card_id` (single) / `card_id:<effect_idx>` (multi/partial); a double-click is one approval; a partial approval is well-defined. | The HITL card posts `DurableExecutor::signal` with the frozen per-effect key; a declined effect is **withheld** (one `EffectApi::apply` per approved effect, AG-8). [02 §5](./02-internals-and-algorithms.md). |
| **`requires_approval` defaults** (8.1, X-6) | Frozen defaults table: Chat post/react = no; cross-subsystem effect inherits the target's default. | Chat's `ToolDef` set uses the frozen defaults; membership/lifecycle gated, post/react/reply ungated; an agent-in-chat invoking another subsystem's tool inherits *that* subsystem's gate. [03 §8](./03-events-contracts-and-glue.md). |
| **Four uniform sandbox guarantees** (8.4, X-6) | Cost gate, per-run attenuated-token attribution, HITL withhold, isolation floor+drill — inherited by every subsystem tool. | Chat agent runs route through `EffectApi` (which reserves) and inherit all four by construction; Chat re-implements none. On HITL resume the workflow re-mints the attenuated token (contract 4.7). [02 §7.1](./02-internals-and-algorithms.md). |
| **Explicit-first dispatch** (8.6, CHAT-1) | A mention notifies; it does not auto-spawn a costed run; implicit auto-dispatch is L-3 (counsel-gated). | A `mention` notifies the agent's inbox; only an explicit action / structured reference dispatches; reserve/settle gates even the explicit run. No auto-spawn path is wired (L-3). [02 §7.1](./02-internals-and-algorithms.md). |
| **CheckStatus / `ci.check.updated`** (5.9, X-1) | CI-owned `CheckStatus` fact, emitted as `ci.check.updated`; Git owns the gate. | Chat is a **consumer for unfurl invalidation only**: it consumes `ci.check.updated` to bust a PR/commit unfurl card and live-update viewers — it does **not** own the gate, the projection table, or the `run_attempt` supersession (those are Git's). [03 §1.3](./03-events-contracts-and-glue.md), [02 §4.4](./02-internals-and-algorithms.md). |
| **The ONE erasure posture** (10.9, X-7) | One platform-wide free-text/immutable-content erasure posture, instantiated per subsystem **by reference**, not restated. | Chat supplies the structural floor (per-subject DEK crypto-shred + pseudonym-map shred + `restrict`) and handles the third-party free-text residual **by reference to contract 10.9** — it writes no fifth chat-specific residual statement. [02 §6.3](./02-internals-and-algorithms.md), [05 §5](./05-hard-problems.md). |
| **Crypto-shred granularity** (11.4) | Per-subject DEK for free-text/body/op-log columns (chat bodies/drafts = the canonical GD-4 case). | `message.body_inline`/`body_nodes` + drafts encrypted under the author's per-subject DEK; `erase(P)` destroys P's DEK → unrecoverable in hot/cold/backups. [01 §3](./01-tech-and-data-model.md), [02 §6.1](./02-internals-and-algorithms.md). |
| **`humanise` sole templating surface** (7.3, OQ-L) | The ICU-MessageFormat registry is the **one** templating surface; every agent-authored message + card registers here. | Chat registers its `humanise` template keys (card strings, agent-message strings, `chat.message.mentioned` etc.); no Chat-private string map; backend-humanised, `ArtifactRef`-paired, per-viewer. [02 §5.1](./02-internals-and-algorithms.md), [03 §4](./03-events-contracts-and-glue.md). |
| **The ONE inbox** (7.1, C-9) | "Activity/Mentions" is a `list_inbox` filter, never a second store. | Chat's Activity/Mentions = `list_inbox(filter = subsystem∈{chat} ∧ reason∈{mentioned, replied, thread_watched, approval_requested})`; one read-state truth, linked to Chat's scroll-state at the mention. [02 §5.3](./02-internals-and-algorithms.md). |
| **Cross-cell pointer bridge** (12.6, OQ-I) | `CrossCellPointer{subject, type, correlation_id, home_cell}`; resolution always cell-local. | Cross-org channels (designed-not-built) ride the frozen bridge; per-viewer resolution is always cell-local. [05 §7](./05-hard-problems.md). |
| **Cross-language harness shim** (1.7) | Frozen as the contract a non-Rust subsystem must satisfy (Chat's BEAM-gateway divergence). | A no-op in the all-Rust default; the frozen shim bounds the BEAM hatch (three-surface, liveness≠readiness, no fire-and-forget emit, `PersonalDataHolder`, resilient-client + `Retry-After`, shed order, forward-only migrations). [01 §1.1](./01-tech-and-data-model.md). |
| **Per-surface shed budgets** (1.11, OQ-K) | Connection-storm + agent-mention-storm budgets named as v1 floors with a reserved human lane. | Chat sets the connection-tier + agent-mention budgets; speculative/presence shed first, message delivery last; humans never queue behind agent runs. Concrete numbers are Chat's P6 call, asserted by the drills. [02 §1.4](./02-internals-and-algorithms.md). |
| **Per-aggregate ordering** (2.3) | Per-conversation total order at production QPS (the D-9 drill). | `aggregate = (conversation_id)`; the outbox `UNIQUE(aggregate, seq)` + ULID `message_id` preserve per-conversation order. [02 §2.2](./02-internals-and-algorithms.md), [03 §1.1](./03-events-contracts-and-glue.md). |
| **Embeddings-as-personal-data erasure** (10.1 / 11.3) | Search purges embeddings (not just FT) on erasure; HYOK `can_derive_plaintext_index()=false` skips indexing. | Chat declares `semantic` indexing; the erasure cascade triggers Search purge+reindex of embeddings; an HYOK tenant structurally skips message indexing. [03 §7](./03-events-contracts-and-glue.md), [02 §6.4](./02-internals-and-algorithms.md). |

**Net:** every Phase-4 CHG-Cn ask is now a frozen contract Chat *implements*, not a request. The mapping
CHG-C1→1.7, CHG-C2→4.3, CHG-C3→3.5, CHG-C4→9.1/9.4, CHG-C5→4.7, CHG-C6→7.6/7.3, CHG-C7→4.4, CHG-C8→10.9,
CHG-C9→1.11/OQ-K, CHG-C10→12.6, CHG-C11→10.1/11.3, CHG-C12→11.4/11.8 is closed.
