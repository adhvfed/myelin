## Canon every prompt in this file assumes (the shared reading set)

Each prompt re-states the precise subset it needs, but all assume the M0 substrate from
[`../00-ledger-overview.md`](../00-ledger-overview.md) §6: the Cargo workspace + the eight glue crates, the
`serve(AppSpec)` harness (three ports, holder auto-registration, ResilientClient, FailStatic, the protected-
human-lane shed order), the transactional outbox + the EventHandler/consumer template, the twelve committed
lints, the contract-coverage scanner, and the failure-injection harness (the 1x/10x/30x load generator + the
scoped-reversible dependency-break injector + the telemetry-assertion library reading contract 1.8). A prompt's
GATE/DRILLS rows are scenarios on that harness; a prompt's DEFINITION OF DONE requires all committed lints green
and the contract-coverage scanner passing.

**The implementation crate.** Tenancy's runtime code lands in two places: the **glue crate `myelin-tenancy`**
(the partition-key types `TenantId`/`Region`/`ResidencyTag` + the `CrossCellPointer` frame — the compile-time
contract carriers every consumer builds against) and a new **service crate `myelin-control-plane`** (the PII-free
registry, `discover`/`place`/`placement_of`/`residency_verify`, the provisioning workflow, the mirror gate, the
discovery cache). The two lints `residency-pin` and `control-plane-pii-free` are authored by Tenancy but hosted in
the substrate/CI lint framework (contract 1.6); their rule + both fixtures are Tenancy's deliverable. Tenancy
implements to the frozen contract shapes — it does not redesign the signatures (EI-01 §1, code-wins-over-docs: if
reality forces a divergence, write it in the crate doc comment and escalate as a whole-workspace contract change).
