## S-1 — The shell *(the frame; funnel target)*
1. **Jobs:** all — the frame every job composes into. 2. **IA (R-06 §3):** top bar (scope selector · `⌘K` · search · Inbox · identity/agent badge · residency cue) + primary rail (`Code·CI·Issues·Knowledge·Chat` + `Home·Inbox·Search` + `[A] Admin`) + contextual sidebar + content + collapsible context pane.
3. **Components:** hosts *all* global surfaces (S-2…S-6). A subsystem owns only its sidebar + content (R-06 §3.2). 4. **Density:** n/a (the frame); the **content region is the only region that earns density** (R-06 §3.3).
5. **Agent:** the agent badge/treatment rides the identity badge (S-6); the context pane hosts the agent panel (R-06 §3.4). 6. **Sovereignty:** the scope indicator **is** the always-on residency cue (T0, R-19 §1.1) — Axis 6 lives partly here.
7. **State set (R-21):** degraded-surface (**fails static** — one subsystem down must not blank the shell, B6); the shell itself never blanks. 8. **A11y/i18n:** landmark/region structure; **whole-shell RTL mirror** (rail → inline-end, context pane → inline-start, breadcrumb chevrons reverse, R-18 §4.3) — the G2 flagship demonstration.
9. **Device (the §8b.4 home, MOB-1…6):** **pin to viewport** (`100vh`/`overflow:hidden`, each region its own scroller, `min-height:0` on scrolling flex children, R-06 §3.5); **contextual sidebar + context pane → mobile drawers** (toggle + backdrop + Escape + route-change auto-close); collapse the other column at the breakpoint (`width:100%` is not a takeover).
10. **Wedge/motion:** the shell is *constant* across subsystems — switching never re-skins the rail (the single most visible coherence cue, R-06 §3.1); `motion.enter`/`exit` on panel open/close. 11. **DoD + switch (the D4 test):** open the same chip/palette/inbox/identity badge in the diff and the roadmap — **identical components** (R-07 §3); switching subsystems never feels like switching apps (the Atlassian stitched-seam regression, R-02 R-SEAM-3).

## S-2 — Command palette (`⌘K`) *(wedge; Axis-3 0.1; funnel candidate)*
1. **Jobs:** E6/E7 (reach any object/action by keyboard). 2. **IA (R-08, R-06 §4.1):** **one palette, every screen** — the primary entry into the §2 tree + the action surface + search entry. 3. **Components:** itself; navigates to chips (R-09); composes the query AST (ADR-07).
4. **Density:** 0.1 (maximally unified by mandate — a per-subsystem palette IS the fracture, R-07 §2). 5. **Agent:** palette actions = the same typed `ToolDef`s agents use (ADR-08 — humans and agents act through one catalogue). 6. **Sovereignty:** **permission-pre-filtered** (ADR-03 — you can only find what you may see, R-08).
7. **State set (R-21 §2a — R-08 9 states):** idle/empty, loading-skeleton, no-results (≠ no-access), error, permission-changed-mid-session, stale/offline, erased/tombstoned, agent-armable. **Four modes** (Navigate/Act/Search/Build-query) with a **mode-pill** (a WORD, not colour). 8. **A11y (R-17 §5.6 palette hard component):** APG combobox+listbox, `aria-activedescendant`, ↑/↓/Home/End/Enter/Esc, focus trapped-then-returned, active option scrolls into view at 200%; one debounced polite live region for count/loading/error; mode-pill announced as word; no-access announces "no access" never the title. **G2:** mode-pill/scope-chip/query-chips mirror via logical-start; kbd-hint → inline-end.
9. **Device:** the palette is keyboard-first (engineer); **on touch, the visible pointer affordances** (rail, buttons) carry non-keyboard PMs (R-01 §1.1 discoverability-cliff trap — P3's second half). 10. **Wedge/motion:** `motion.enter` 140ms (instant under reduced-motion); the palette "simply there" (speed *is* delight, R-12 §7.1). 11. **DoD + switch:** a power user crosses the whole flow on the keyboard faster than Linear; a PM still discovers the same actions via visible affordances (the discoverability-cliff avoided).

## S-4 — Unified notifications inbox ("what needs *me*") *(Axis-3 0.2; funnel D7 surface)*
1. **Jobs:** M5 (one prioritised inbox), D3 (engineer vs EM weighting), agent gates. 2. **IA (R-10 §4, R-06 §4.3):** `[G] Inbox` — the single cross-subsystem aggregation; a per-role landing target. 3. **Components:** itself; chips; the HITL card (a second home, S-9/H-9).
4. **Density:** 0.2 — earns almost none (the anti-firehose spine must be **identical everywhere or the calm promise dies**, R-07 §2). 5. **Agent:** **agent volume routed OUT of the main stream** (R-13 §B.4); gates surface here so a human gate is never missed. 6. **Sovereignty:** subject-erased/restricted items degrade gracefully.
7. **State set (R-21 §2g — inbox **owns** storm, col 13):** empty/inbox-zero (**quiet** reward "caught up", **never confetti**, R-22 anti-wedge); deduped-group ("+N more"); **storm/30×-agent-surge** (collapses, agent lane sheds first via 429+Retry-After). 8. **A11y/i18n:** new-item live region politeness; single-action triage (done/snooze/mute/go) keyboard-first; **G2** humanised "why-fired" strings, locale-aware times.
9. **Device:** **a primary mobile surface** — triage + approve-gate from a phone (one-action); MOB-1 row-actions touch-reachable. 10. **Wedge/motion:** **W3 (notification carries *why* + pre-fetched next hop)** — "because you're assigned"; click opens the target *warm* (CA-3); `motion` inbox-item-arrive subtle. 11. **DoD + switch (D7/R-02 R-NOISE):** **one** prioritised inbox (FAIL if multiple parallel streams); **deterministic explainable ranking** (`reason→base→class`, not ML black box, R-13 §B.5); every item answers "why am I getting this"; bursts deduped not enumerated; the Teams-firehose regression dissolved.

## S-11 — GDPR / data-rights (DSR) console *(governance flagship; D9; funnel Axis-6 surface)*
1. **Jobs:** G5 (locate/export a subject across all subsystems), G6 (erase preserving integrity), G10 (offboard lawfully). Flow **F-GOV-1** §6 (the DPO view + the data-subject view, the D4 pair). 2. **IA (R-19 §2):** `[A] GDPR`; the DPO's primary surface; **5 tabs over one subject** (Locate / Export / Rectify / Restrict / Erase) + a persistent **receipt rail** + a **deadline clock** (Art. 12(3)).
3. **Components:** views (per-holder inventory), overlays (the consequence dialog), chip (per-holder rows). 4. **Density:** 0.4 — earns its own dense layout via J1 (DSR fan-out is a genuinely distinct information artifact, R-07 §2).
5. **Agent:** agent-memory is a PersonalDataHolder (erased in fan-out); agent-use suppressed under Restrict (R-19 §2). 6. **Sovereignty (the whole point):** per-holder rows tagged with cell + residency; **export stays in-region**; the consequence dialog shows honestly what crypto-shreds vs tombstones vs keeps pseudonymised authorship (R-19 §7.1).
7. **State set (R-21 §2g — DSR console **owns** erasure outcome, col 5):** per-holder progress ("9/10 complete · Chat timed out — retry"); **partial-holder-failure isolated** (saga, never silent partial — completeness is the legal point, R-04 §6.2); integrity-guard blocks if erasure would break the audit carve-out; deadline-at-risk escalates (<72h surfaced in DPO inbox). 8. **A11y (regulated surface — G1 hard):** fully keyboard-operable; consequence dialog = `alertdialog`; **G2** locale-aware deadline + business-calendar (R-18 §5.2, load-bearing).
9. **Device:** **desktop-mainly (MOB-6)** — the inventory *read* view on mobile; **destructive actions (erase) defer to desktop** with a clear "open on a larger screen to act". 10. **Motion:** per-holder progress (not spinner-on-blank); no celebratory motion. 11. **DoD + switch (D9):** one subject → one inventory → one verifiable receipt (the N-manual-searches-no-proof regression dissolved, F-GOV-1 🔪); a DPO **trusts the receipt/completeness at a glance** — **`[UNDER-EVIDENCED]`/`[DEFERRED-UNTIL-USERS]`** (R-19 §9 regulated-buyer review is the real test).

## S-9 — Agent governance console + kill-switch
1. **Jobs:** G4 (see which agents exist, scopes, budgets, autonomy; org-level kill-switch). Flow F-AGT-1 (governance lens). 2. **IA (R-15 §4, R-06 §4.5):** `[A] Agents`; the governed face of the agent layer (the ambient face is the badge everywhere). 3. **Components:** views (roster), scope/budget inspector, overlays (kill-switch confirm).
4. **Density:** 0.4. 5. **Agent (the subject):** roster (agents as Principals with treatment); autonomy policy (suggest-by-default, gated-to-raise); **kill-switch** (pause-all/this-agent, one-click + confirm for org-wide); budget/loop-guard states governance-visible (R-15 §3). 6. **Sovereignty:** "what may this agent touch, on whose authority, until when" (scope/delegation inspector).
7. **State set (R-21 §2g):** budget-exceeded/loop-guard-tripped visible; agent-audit deep-link. 8. **A11y/i18n:** kill-switch prominent + keyboard-reachable; agent treatment as text; humanised. 9. **Device:** **kill-switch reachable on mobile** (it's an emergency control); roster read-friendly; policy-editing desktop-mainly.
10. **Motion:** none decorative; settle on policy save. 11. **DoD + switch (R-02 R-AGT, D6/D9):** **one inventory** of every agent + scope + budget + activity + kill-switch (FAIL if agent presence is discoverable only per-surface — the Atlassian agent-sprawl retrofit); every agent born-governed; "what did this agent touch?" answerable inline (R-AGT-3).
