# Myelin — Full Platform Review

_Generated 2026-07-06 · multi-agent code + UX review, adversarially verified._

## Overall health

Myelin presents a striking bimodal profile. Its backend is unusually disciplined — invariant-driven, fail-closed, and mutation-tested — with genuinely robust cross-tenant isolation (tenant-from-token everywhere), a mature GDPR engine, correct-by-construction event/outbox delivery, and strong path-traversal and injection defenses. Across 24 deeply-reviewed units, only 3 critical and 11 high findings surfaced, and the critical trio is entirely in one place: the flagship Git/PR user-facing surface, which is materially incomplete (pull requests are undiscoverable, there is no diff, and the differentiating context pane does not exist). The most important structural caveat is that a large share of the security-relevant findings are latent-until-wired: the real backends sit behind an `integration` feature flag, several holders are in-memory floor models, and `main.rs` currently injects an AllowAll authorizer — so the object-level authorization gap is a model/wiring gap today, not a live exploit, but it is baked into the declared template every subsystem copies. Health is strong at the substrate and weak at the seam where the product meets the user; the platform is far from shippable as a flagship but its foundations are sound.

## Executive summary

**The core is excellent; the product surface and the last mile of authorization are not.** Myelin's substrate — identity/tenancy, storage RLS, event bus, GDPR engine, agent fabric, search's lexical path, refs — reviews as genuinely well-engineered: fail-closed gates, opaque PII-free value types, emit-iff-committed delivery, and heavy mutation testing. Cross-tenant isolation is real, not placeholder: scope is always derived from the verified token, never from path or body.

**The flagship Git/PR experience is the headline gap.** Three CONFIRMED criticals cluster here: PRs have no list and no link anywhere (G-6 has no front door), there is no PR diff/files-changed view (the core review action is absent), and the PR overview ships none of its differentiating context (description, linked issue/run/doc, discussion, commits). Compounding highs: subdirectories are dead ends (most real repos un-browsable), and four of five nav destinations 404 into raw framework chrome. The wedge the whole product is built around is not yet usable.

**The platform's own hard principles have CONFIRMED holes, mostly latent.** Object-level (Zanzibar-style) authorization does not exist at the edge — re-authorization is action-string only, and because `git_edge` is the explicitly-declared template for every subsystem, any principal who passes a coarse action check can reach every repo/PR/blob in their tenant. Two deeper defects rhyme with it: identity's `check()` authorizes on the bare trailing id (cross-artifact confusion), and the fail-static authz cache aliases distinct keys on a 64-bit hash (potential cross-tenant grant). Agents-as-first-class governance leaks: the MCP HITL gate trusts a caller-supplied boolean (self-approval of `git.merge`), and batch partial-approval can apply a declined sibling effect. GDPR-by-construction has real edges: the erasure ledger records submission (not completion) time, so a backup restore can resurrect an erased subject — the module's own "gravest failure."

**Compute-but-don't-enforce recurs.** CI's egress/metadata-SSRF allowlist is derived but never applied to the datapath; git DSR receipts hardcode `holders_hit = ALL`; a gVisor drill uses a no-op seccomp. Most of these are inert until wired, but they weaken the attestations that are supposed to prove safety.

**Recommendation:** treat the backend as a strong asset, but gate any flagship claim on (1) completing the Git/PR surface, (2) landing object-level authz before removing AllowAll, and (3) closing the enforce-what-you-compute and erasure-timestamp gaps.

## Top risks

- **The flagship Git/PR surface does not deliver its core job** — _Frontend — Git/PR UX (ux-git)_ · **critical** — Three CONFIRMED criticals in one surface: pull requests have no list and no link from anywhere (unreachable without an out-of-band PR number), there is no PR diff/files-changed view (the reviewer cannot see what changed), and the PR overview renders none of its differentiating context pane (linked issue/run/doc, discussion, commits). The wedge the product is built on is structurally absent, not merely rough.
- **Backup restore can resurrect a GDPR-erased subject** — _GDPR engine (myelin-gdpr-service/fanout.rs)_ · **high** — CONFIRMED: the erasure ledger records the DSR SUBMISSION time as the post-restore re-erasure offset instead of the completion time. The legal-hold path returns early at AwaitingHolders and `drive` is re-invoked days/weeks later, so the submit→complete window is real. A restore inside that window silently resurrects an erased subject — the module's self-described 'gravest data-handling failure' and a direct Art. 17 breach.
- **CI egress / metadata-SSRF block is computed but never enforced at runtime** — _CI sandbox (myelin-ci-sandbox/firecracker.rs)_ · **high** — CONFIRMED: for any job opting into egress the guest gets an effectively unfiltered NIC. `assert_enforced` only rejects a literally-named blocked host; nothing stops the guest reaching cloud metadata, cross-tenant, or control-plane endpoints by IP/DNS at runtime. The advertised AG-D4 SSRF/isolation guarantee depends entirely on out-of-crate host tooling that this review could not see.
- **No object-level authorization at the edge — and it is the template every subsystem copies** — _Edge/substrate authz (myelin-substrate/topology.rs, myelin-edge/gateway.rs)_ · **high** — CONFIRMED: edge re-authorization is action-string only, so within a tenant any principal passing the coarse action check can read every repo/PR/blob/search hit regardless of per-object grants. `git_edge` is the explicitly-declared template for all subsystems, propagating the gap. Latent today (main.rs injects an AllowAll authorizer, real Identity-M1 unwired) but architectural. Rhymes with identity check() authorizing on the bare trailing id and SSE scope being tenant-coarse.
- **Semantic/RAG search ACL filter leaks denied sub-artifacts** — _Search vector path (myelin-search/engine.rs)_ · **high** — CONFIRMED: `AclFilter::admits` (the semantic/RAG traversal predicate) matches only `doc_id`, while the lexical posting-list clause matches `doc_id OR acl_object`. Under a Difference/NotIds deny-set on a parent, an embedded sub-artifact (Knowledge block, issue sub-item) is excluded lexically but admitted by the vector path — a per-permission content leak (and the inverse hides permitted docs).
- **Git crash reconciler mishandles deleted-then-recreated refs** — _Git hosting (myelin-git/reconcile.rs)_ · **high** — CONFIRMED: the reconciler uses reflog length as update_seq. A healthy repo whose branch was ever deleted and recreated makes reconcile_refs return CasMismatch and abort recovery, or — under burst-crash ordering — silently skip the committed recreate and leave the ref DELETED. The reconciler runs on every restart before the durable store serves the front door, so this is a data-integrity/availability hazard on the primary git path.
- **Autonomous agents can bypass human-in-the-loop approval** — _Agent governance (myelin-mcp/server.rs, myelin-agent-service/hitl_batch.rs)_ · **medium** — Two CONFIRMED holes in agents-as-first-class governance: the MCP HITL gate trusts a caller-supplied boolean, so an agent can set approval.granted=true to clear the gate on a requires_approval tool (git.merge); and batch partial-approval can apply a DECLINED sibling effect that shares a tool name with an approved one. Consequential for gated tools (git.merge, knowledge.publish, ci.deploy). Bounded today by the skeleton EffectApi, but the gate itself is defeatable by design.
- **Frontend auth bypass risk and EN 301 549 accessibility failures** — _Frontend web/design system (src/lib/auth.ts, CommandPalette.tsx, commits/[ref].tsx)_ · **medium** — CONFIRMED: the dev-login action mints a full authenticated session with no environment guard — if shipped with real OIDC deferred, anyone on the network can self-issue a session (full auth bypass). Separately, the command-palette input suppresses its focus ring inline (the one control the design manual singles out), the nav-rail active state over-spends accent, and commit links fail AA contrast in light theme — concrete WCAG 1.4.3 / EN 301 549 eligibility failures for the EU public-sector market.
- **Workflow budget reservations leak, starving runs** — _Flow engine (myelin-flow/budget.rs)_ · **medium** — PLAUSIBLE/CONFIRMED pair: metered_activity permanently loses its full cost reservation when the inner activity exhausts retries, with nothing billed. A run that keeps dispatching against the same wallet cumulatively drains it until BudgetGate::reserve refuses ALL further dispatches — a run can starve itself via ordinary transient failures. Related durability concern: reserve/settle mutates the durable ledger outside the FLOW-D5 co-commit, so a crash can leave the ledger and journal disagreeing.

## Cross-cutting themes

- **A disciplined backend married to an unfinished product surface** — The substrate is invariant-driven, fail-closed, and mutation-tested — identity, storage RLS, event bus, GDPR engine, agent fabric, and search's lexical path all review as genuinely strong. Nearly every critical and a large share of highs live instead in the user-facing Git/PR UX and the frontend a11y layer. The gap is not code quality broadly; it is that the flagship experience and its last-mile polish lag the engine by a wide margin.
- **Action-scoped authorization with no object-level check — propagated by template** — The edge re-authorizes on an action string only, never an object. Because git_edge is the declared template, this under-enforcement is copied into every subsystem's future wiring. It recurs at deeper layers too: identity's check() authorizes on the bare trailing id (cross-artifact confusion), the fail-static cache aliases keys on a 64-bit hash, query's EventMatcher matches on last-segment id, and SSE scope is tenant-coarse. Cross-tenant isolation holds; intra-tenant object isolation is the systemic soft spot.
- **Latent-until-wired: correct models behind an integration flag and an AllowAll authorizer** — Many security findings depend on production wiring not yet present: real backends sit behind the `integration` feature flag, several PersonalDataHolders are in-memory floor models, SSO routes to RefuseUnsupported, human login is unwired, and main.rs injects an AllowAll authorizer. This means several 'holes' are model/consistency divergences today rather than live exploits — but it also means the safety these components advertise has not yet been exercised in a real path, so risk transfers to the integration milestone rather than disappearing.
- **Compute-but-don't-enforce and self-fulfilling attestations** — Several safety values are derived and then not applied, weakening the very proofs meant to guarantee them: CI's egress allowlist is computed but never enforced on the datapath, the positioner's viewport clamp is returned but no consumer applies it, git DSR receipts hardcode holders_hit = ALL (so the NotGreen gate cannot detect a skipped holder), a gVisor escape drill uses a no-op seccomp, and erase receipts count candidates rather than actual evictions. The attestations pass more easily than the guarantees warrant.
- **GDPR completeness edges around residency, timing, and holder registration** — The erasure engine is mature but has real seams: the ledger records submission (not completion) time enabling post-restore resurrection, refs and an fr-par region are hardcoded so non-fr-par tenants erase the wrong partition, DSR completion never reconciles receipts against the data-map so a mapped-but-unregistered holder is silently skipped while reporting green, and the compile-time untagged-PII guard only fires on exact field-name matches. Individually mostly low/medium and partly latent, but collectively they chip at the 'GDPR-safe by construction' claim.
- **SQL string interpolation and secret exposure as recurring latent footguns** — Several crates build SQL by interpolating identifiers or render predicates with unescaped single quotes (storage rls, knowledge block_tree, storage migration missing TRUNCATE) — injection-safe only because no live path executes them yet, but a standing invitation for a future driver to copy the wrong shape. Alongside, config secrets (DB password, S3 keys) are exposed via derived Debug and the CLI writes its bearer token pre-chmod and speaks plaintext HTTP. None are actively exploited, but they contradict the codebase's own otherwise-consistent injection-safe and secret-hygiene conventions.
