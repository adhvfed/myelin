# Event bus & substrate (myelin-events, myelin-substrate)

_The event-bus (myelin-events) and substrate (myelin-substrate) crates are unusually disciplined: delivery semantics (emit-iff-committed outbox, stable-id broker dedup, per-consumer dedup ledger with revert-on-retry), per-aggregate commit-time seq allocation (gap-free), bounded prefetch + per-tenant fairness, firehose resume-cursor zero-loss/resync-required, and the tenant-from-token IDOR chokepoint are all correct-by-construction and thoroughly drilled. Durability/ordering/backpressure/tenant-partitioning invariants hold up under scrutiny. One real defect stands out: the fail-static authorization availability cache keys entries solely on a 64-bit hash of the key without storing or comparing the key itself, so distinct authz keys can alias a cached grant during a dependency hiccup. Most other observations (in-memory floors, Rc/RefCell single-thread firehose, minor lag-accounting drift under repeated throttle) are explicitly documented floors, not defects._

**Kept findings:** 1  (🟡 1 medium)

### 1. 🟡 Fail-static authz cache keys on a 64-bit hash with no key equality — distinct authz keys can alias

- **Severity:** medium  ·  **Verdict:** ✅ CONFIRMED  ·  **Category:** security
- **Location:** `crates/myelin-substrate/src/fail_static.rs:278`

**What:** `FailStatic<T, C>` stores its cache as `Mutex<HashMap<u64, Entry<T>>>` (line 278). The `u64` bucket is the output of `hash_key` (lines 482-487), which feeds the caller's key through a `std::collections::hash_map::DefaultHasher` and returns `h.finish()`. The original key `K` is deliberately not stored (comment line 279: "so `K` need not be stored"). Both `get()` (line 383-404, `bucket = hash_key(&key)`) and `serve_from_cache()` (line 408-449) look up purely by that `u64` and never compare the real key — `cache.get(&bucket)` on line 415 returns whatever entry lives in that bucket. So any two distinct keys whose 64-bit hashes collide share one entry. This same `FailStatic<CoarseAuthz, C>` is the `inner` of `FailStaticAuthz` (fail_static_authz.rs line 146), whose keys are the `(tenant, region, subject, permission@object)` authz discriminator (documented lines 214-215, e.g. `"acme|eu|alice|read@doc:1"`), and the `BoundedStale` path routes straight into `self.inner.get(key, ...)` (line 265). On a hiccup, a colliding key would be served another key's cached coarse decision. NOTE: `DefaultHasher` here is unseeded (fixed-key SipHash, not the randomized `RandomState`), so collisions are deterministic/reproducible rather than randomized per-process — but engineering a collision against a specific victim key is still a ~2^64 preimage search.

**Impact:** During a transient Identity hiccup, a `BoundedStale` authz read for key K2 could be answered with a coarse grant actually cached for a different key K1 that hashes to the same 64-bit bucket. If K1 cached `Allow` and K2 belongs to a different tenant/subject/object that should be `Deny`, the caller is granted access it should not have — a cross-tenant/cross-actor authorization escalation, directly against the platform's hard multi-tenant-isolation principle. However the practical probability is very low: accidental birthday collision is ~N^2/2^64 (negligible for realistic cache sizes), and deliberate exploitation requires a ~2^64 preimage against SipHash. The defect is a genuine unbounded design choice (aliasing is never checked anywhere), but the escalation only manifests on a hash collision AND during a dependency hiccup AND when the two aliased decisions disagree.

**Fix:** Key the cache on the full key: `HashMap<K, Entry<T>>` with `K: Hash + Eq` (the authz key already satisfies this), or store the key alongside the bucket and verify `stored_key == requested_key` before serving. Never serve a cached authorization decision without confirming the stored key equals the requested key. Strengthen the tests: the existing `distinct_keys_do_not_share_a_cache_bucket` (fail_static.rs line 771, fail_static_authz.rs line 514) only checks hand-picked non-colliding strings and cannot establish collision-freedom — add a case with two keys engineered to the same bucket (or a property test).
